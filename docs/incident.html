From Alert to Recovery: A Slow Java Service

A controlled incident on QuoteLab. Prometheus caught slow quotes, Nagios checked availability, and AWX ran a targeted recovery after approval.

Original QuoteLab CPU investigation

217 msBaseline p95
1,769 msIncident p95
276 msRecovery p95
64 sLoad start to observed alert
What happened
Four lab workers competed with the Java service for CPU during a fixed-rate HTTP test. A systemd quota capped their combined use at 1.4 logical CPUs.
How I investigated
I compared client p95 and Linux CPU usage in Grafana, then used AWX to inspect the workload and service states. Nagios independently checked the HTTP health endpoint.
What I found
In this run, p95 rose from 217 to 1,769 ms. Nagios reported OK on 4 checks while the latency alert was firing and the workers were still active.
What I changed
AWX stopped the lab CPU workers after an approval step. The alert cleared 50 seconds later, and stable recovery p95 was 276 ms.

      What AWX and Nagios recorded

      Mean host CPU execution rose from 38.4% to 98.9%. Mean Java handler wall time rose from 164.3 to 344.3 ms, while handler CPU time went from 152.3 to 176.0 ms. The running workers, the gap between wall time and CPU time, and recovery after stopping the workers support CPU contention as the cause in this lab.

      Scope and reproducibility
      
    
      The request generator offered four requests per second on the two-vCPU QuoteLab VM. It measured end-to-end HTTP latency over loopback and retained client dispatch delay and server handler wall and CPU times. The 20-second rolling alert used successful quote samples, a 500 ms lab threshold, and a 15-second hold. It stayed firing for 30 seconds after the rule condition dropped away, so alert clearance includes that delay.
      
    
      The table uses per-request observations from stable phase windows. The charts show the live rolling values, so they can lag a phase boundary. Nagios tested HTTP status and the expected health body. These measurements describe one controlled incident, with the request generator sharing the same VM as the app. The probe's skipped-offer counter rose by 5 across the sampled window.
